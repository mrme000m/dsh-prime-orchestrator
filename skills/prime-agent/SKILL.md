## When to Use
Use when delegating work to a prime-agent session beyond what the `prime_agent` tool covers, steering or inspecting a running prime-agent session, managing its daemon, coordinating multiple parallel prime-agent sessions, or using its RLM recursive-subagent / agent-to-agent messaging capabilities. Repo source lives at /Volumes/ExMac/code/Agents/prime-agent (launcher prime-agent.sh); the installed binary is `prime-agent` (override with PRIME_AGENT_BIN or the preset row's config.bin).

## Procedure
1. DELEGATE/MONITOR/COORDINATE through the `prime_agent` tool first. Actions:
   - `delegate` starts a background `prime-agent --mode json <task>` session and accepts capability flags (model, provider, thinking, goal, goalTokenBudget, continue, resume, extensions[], skills[], appendSystemPrompt[], offline, autonomous + autonomousGates[]/autonomousMaxTurns/autonomousMaxTokens/autonomousTimeoutMs/autonomousGateRetries/autonomousGateTimeoutMs/autonomousMaxContinuations).
   - `agents` returns a structured roster of daemon-managed and saved sessions — each row's `id` is its daemon active session id (the address for send_message/heartbeats), plus name, cwd, model, activity, rlm depth, parent, and heartbeat flags. Use it to discover parallel workers before coordinating.
   - `send` delivers a message to a session/agent by name or id via the CLI (agent-to-agent delivery; slash commands NOT parsed; `from` names the sender; `delivery` steer/follow_up).
   - `send_message` delivers an agent-to-agent message over the daemon socket and returns a delivery receipt (`target` = agent name or active session id; `delivery` steer interrupts, follow_up queues).
   - `agent_messages` controls the agent-message inbox: `status` reads the safety state (paused + queue/rate limits), `pause`/`resume` gate all agent messages daemon-wide, `clear` drops one session's queued agent messages.
   - `heartbeats` lists all heartbeat/scheduled jobs; `heartbeat_get` reads one session's current heartbeat (schedule/prompt/delivery/run count); `heartbeat_set` creates or REPLACES a session's heartbeat (re-issuing it is how you self-update to a new checkpoint); `heartbeat_action` pause/resume/stop/cancel/clear.
   - `prompt` delivers new work or a session slash command to a RUNNING daemon session (`agent` + `message`; session commands like /goal /autonomous /refine are parsed); `goal_set`/`goal_action` set and manage a running session's persistent goal; `children` lists a session's own rlm() subagents; `abort` cancels a running turn. `status`/`events`/`sessions`/`send`/`stop`/`doctor` cover the common loop; `goal`/`session` are read-only forensics of any daemon-backed session's goal lifecycle, compaction, and idle state (they read `~/.prime/agent/sessions/<id>.jsonl` directly, no daemon socket needed). `shutdown` (force:true) stops every agent and service.
   - `refine` runs `/refine` on a session (`agent` + optional `instructions`/`rollbackId`/`global`); `rename` sets a session's name (`agent` + `name`); `compact` compacts a session's context now (`agent` + optional `instructions`); `wait_for_idle` blocks until a session reaches its idle state (`agent`); `saved_sessions` lists saved (draft) sessions (`scope` current/all). All five talk to the daemon socket, so they need a running daemon.
   Delegation event logs land in `~/.dsh/prime-orchestrator/delegations/<id>.jsonl`, and the `/prime` route on this harness's web server renders the same state (plus doctor and session inspector cards).
2. Self-updating heartbeats: prime-agent's `heartbeat_set` REPLACES a session's existing heartbeat (one heartbeat per session; a new call carries the previous deliveryMode forward when none is given). To move a long-running session's checkpoint forward: read its latest reply via `events`/`session`, extract the new checkpoint it reports, then re-issue `heartbeat_set` with the updated schedule/message. Read the current state first with `heartbeat_get`. Clear a finished session's heartbeat with `heartbeat_action` action `clear` so it stops prompting. A heartbeat set on a subagent's active session id is a nested (`rlm_heartbeat`) job, managed by the same routes.
3. Multi-agent coordination: fan out one delegated worker per independent part of the code, each with a distinct scope and knowledge of the other workers' file areas. Find each worker's `id` with `agents`, then use `send_message` to pass results/warnings/integration instructions between them (orchestrator owns hand-offs; workers also message each other directly). Have workers write results to distinct files and report short completion summaries; read those files yourself to integrate.
4. Control a RUNNING session: the prime_agent tool covers the daemon socket natively. `prompt` (agent + message, delivery steer/follow_up/default-queue) delivers new work or a session slash command — /goal, /autonomous, /refine, /compact, /rlm-max-depth, /heartbeat are parsed at the session level (not TUI-only). `goal_set` (agent + goal + optional tokenBudget) sets a persistent goal on a running session; `goal_action` (agent + goalControlAction pause/resume/clear/stop/status) manages it. `children` (agent) lists the session's own rlm() subagents (name, status, model, token/tool counts, answer preview, sessionDir); `child_action` (agent + childId + op cancel/delete) manages one of them. `abort` (agent) cancels the current turn without stopping the session. `messages` (agent; last:true for the final assistant text) reads the conversation; `queue`/`queue_action` (op clear/abort_clear) inspect or drop pending steering/follow-up input; `models`/`set_model` (provider+modelId or cycle, optional thinkingLevel) switch the model mid-session; `rlm_depth` (agent; optional maxDepth + global) reads or caps the session's own subagent recursion; `fork_points` + `fork` (entryId, position before/at) branch the session at an earlier user message to retry a different approach; `export` (format html/jsonl, optional outputPath) writes the transcript to disk; `saved_session_action` (op rename/delete, sessionPath from saved_sessions) housekeeps finished sessions. The public CLI surface only has agents/list/attach/stop/rename/send/schedule/status/doctor/shutdown — `daemon` subcommands are REMOVED.
5. If a prompt fails with 'Cannot admit a session action while queued session input is suspended' (session stuck after an update-restart abort), the tool retries once through `{type:'resume_queue', activeSessionId}` automatically; the manual form is `client.request({type:'resume_queue', activeSessionId})` — it clears the suspension even when it reports 'No queued work to resume' — then retry the prompt.
6. Verify a goal pause: tail the session file (`~/.prime/agent/sessions/<id>.jsonl`) for a `thread_goal_state` custom event with `status:'paused'` and a `session_slash_command_result` 'Goal paused: ...' message.
7. Inspect what's RUNNING: `prime-agent status` shows daemon socket/pid/version/session count; `ps aux | grep -i prime-agent` shows the daemon (ppid 1, started once), the session worker (parent = daemon) and its child `kernel-venv/bin/python -m ipykernel_launcher` (a live session has a kernel); `prime-agent agents` may list nothing even with an active session. Session files live in `~/.prime/agent/sessions/*.jsonl` (first line `{type:'session', cwd, git}` = start info; mtime = last write; big file = actively worked). Worker/daemon logs: `~/.prime/agent/logs/worker-*.log`, `~/.prime/agent/logs/agent.jsonl`; active session lease under `~/.prime/agent/session-leases/`.
8. Inspect what's INSIDE a session: the JSONL is event-typed — `session` (header), `model_change`, `thinking_level_change`, `message` (roles user/assistant/toolResult; content blocks text/thinking/toolCall/toolResult, toolCall has arguments.code), `custom_message` (goal_context, refinement_outcome, session_slash_command, session_slash_command_result), `custom` (thread_goal_state → data.status/data.goalId), `compaction` (carries goal/objective summaries), `git_state`, `agent_status` (taskState needs_input = idle, basedOnMessageCount = msg count). Parse with a JSONL script rather than reading raw (a long-lived goal session grows to 15MB+/10k events). Idle = trailing agent_status needs_input heartbeats; last non-status event = last real work.
9. Long-running goal sessions: goals rotate — when one completes (compaction summary 'COMPLETED', final evidence like realized PnL), a fresh goal id replaces it; check thread_goal_state data.goalId for the CURRENT id. Goal context is injected each turn via custom_message goal_context. /refine updates session memory (refinement_outcome).
## Pitfalls
- prime-agent executes model-generated Python and project commands with your user permissions — worker/kernel isolation is lifecycle recovery, NOT a security sandbox. Use disposable clones/worktrees for risky work; untrusted code needs an external sandbox.
- In RPC mode, during active streaming a `prompt` without `streamingBehavior` returns an error — use steer or followUp to queue. Extension commands run immediately even while streaming; skill/template commands are expanded.
- RPC framing is strict JSONL with LF only; Node's readline also splits on U+2028/U+2029 which are legal inside JSON strings — split on \n yourself.
- `prime-agent -p` without credentials or with a stale auth will fail silently-ish — run `prime-agent /login` or set the provider API key env var first. `--offline` disables startup network ops but does NOT supply model credentials.
- rlm() never returns the child's answer — it returns a handle at admission; children must explicitly reply via agent_message.send or write results to files, or you hang waiting.
- Autonomous limits are ceilings, not success criteria: reaching a limit means the run stopped, not that the task passed. A passing `--autonomous-gate` is what verifies completion.
- The installed binary at /Volumes/Spare/npm/global/bin/prime-agent may lag the source checkout in /Volumes/ExMac/code/Agents/prime-agent; use ./prime-agent.sh from source for the newest features.
- The daemon `get_state`/prompt command replies use the SHORT daemon activeSessionId (e.g. 9855721c70f0), not the full session id (01a0342c-…); attach resolves the full id. The daemon state has fields id/lifecycle/activity/isSessionActive/lastActivityAt/sessionId/sessionFile/cwd/model — no goal field.
- A session can be stuck in `_sessionInputPumpSuspended` (set by abortForUpdateRestart) with lifecycle 'live' but input admission rejected; resume_queue clears it. Symptom: session idle (needs_input heartbeats) with last real activity hours earlier and prompt rejects.
- `prime-agent send <agent> <message>` is agent-to-agent messaging (deliveryMode steer) — slash commands are NOT parsed there; the model just sees the text. Use the daemon prompt route for slash commands.
- Agent messages are bounded: max 16384 chars, 20 pending per session, a 3-message/1s rate-limit refill. `agent_messages status` reports these limits and whether delivery is paused; `agent_messages pause` gates all agent messages daemon-wide (use it to freeze cross-worker traffic while integrating).
- Session files are outside the project root; ctx_execute_file blocks them — copy into the workspace first to analyze with a JSONL script, or use bash+python.
## Verification
1. `prime-agent --version` prints a version (0.8.0 on this host).
2. `prime-agent -p "Say hi in one line"` returns a short response and exits 0.
3. `prime-agent --mode json "List files" 2>/dev/null | jq -c 'select(.type=="agent_end")'` emits one agent_end JSON line.
4. `printf '{"type":"get_state"}\n' | prime-agent --mode rpc --no-session` returns a response with success:true (works even before auth).
5. `prime-agent agents` lists running/idle sessions without error.
6. `prime-agent doctor` reports healthy background services (daemon/supervisor running).
